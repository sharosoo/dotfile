# Product Review Research

## Overview

쇼핑몰, YouTube, 디시인사이드, Reddit, 블로그 등에서 실제 사용 후기를 교차 조사해 반복되는 장단점과 사용 조건을 찾는다. 별점 평균이나 홍보 문구를 요약하는 것이 아니라 **정확한 제품 식별 → 독립된 원문 수집 → 광고·중복 판별 → 상충 의견 설명**까지 수행한다.

최종 답은 다음을 밝혀야 한다.

1. 어떤 사람과 사용 조건에 잘 맞는가
2. 어떤 불편·고장·비용이 여러 독립 출처에서 반복되는가
3. 구매 전에 확인해야 할 불확실성이 무엇인가
4. 사용자 용도에 적합한가

## When to Use

- 여러 쇼핑몰과 커뮤니티의 실사용 후기를 모아 달라고 할 때
- 장기 사용, 내구성, 소음, 발열, 착용감, AS 경험을 확인할 때
- 광고성 리뷰를 걸러 여러 제품을 비교할 때
- 특정 불만이 반복되는 현상인지 단일 사례인지 판단할 때

가격·품절 확인이 주목적이면 `korea-shopping-price-stock`을 사용한다. 사양만 필요하면 제조사 공식 문서를 먼저 본다. 의학·법적 안전성은 후기만으로 판정하지 않는다.

## 1. 제품을 정확히 식별한다

검색 전에 다음을 고정한다.

| 항목 | 확인 내용 |
|---|---|
| 정식 제품명 | 한국명, 영문명, 별칭 |
| 모델 번호 | SKU, 품번, 세대, 출시 연도 |
| 옵션 | 용량, 크기, 재질, 유무선, 색상별 기능 차이 |
| 지역판 | 국내 정발, 해외판, 리브랜딩 여부 |
| 혼동 대상 | 이전 세대, Pro·Plus, 비슷한 품번 |

세대·옵션·지역판이 다르면 같은 제품으로 합치지 않는다.

**완료 기준:** 검색에 쓸 정확한 모델명과 제외할 유사 모델이 정리되어 있다.

## 2. 사용 조건별 조사 질문을 만든다

제품군에 맞는 실패 조건을 4~8개 정한다.

- 전자기기: 발열, 배터리 열화, 연결 끊김, 펌웨어, 소음, AS
- 의자·가구: 체형 적합성, 장시간 통증, 흔들림, 조립, 마감
- 주방용품: 세척, 코팅 내구성, 누수, 실제 용량, 소모품 비용
- 의류·신발: 실측, 발볼, 소재감, 세탁 후 변형, 계절성
- 생활가전: 실제 소음, 청소 난이도, 필터 가격, 고장 시점

사용자가 용도를 말했다면 그 조건을 우선한다. 모르면 일반적인 장기 사용 문제를 조사하고 가정임을 밝힌다.

**완료 기준:** 최종 답에서 판정할 질문이 명시되어 있다.

## 3. 출처별로 따로 검색한다

한국어와 영어를 함께 사용하고 한 번의 통합 검색으로 끝내지 않는다.

### 공통 검색어

- `"정확한 모델명" 후기`
- `"정확한 모델명" 단점 OR 불량 OR 고장`
- `"정확한 모델명" 장기 사용 OR 6개월 OR 1년`
- `"exact model" review`
- `"exact model" problems OR issue OR failure OR long term`
- 제품명 외에 모델 번호로도 검색

### 채널별 조사

| 채널 | 검색 예시 | 확인할 내용 |
|---|---|---|
| 국내 쇼핑몰 | 모델명 + 쿠팡·11번가·G마켓 | 초기 불량, 배송과 제품 문제, 구매자 사진 |
| YouTube | 모델명 + 리뷰·long term | 사용 모습, 소리·크기, 비교, 장기 경험 |
| 디시인사이드 | `site:dcinside.com 모델명` | 반복 불만, 설정 팁, 고장 사례 |
| Reddit | `site:reddit.com 모델명` | 장기 사용, 해외판 차이, 후속 댓글 |
| 블로그·카페 | 모델명 + 내돈내산·단점·고장 | 국내 AS, 설치, 사용 맥락 |
| 제조사 지원 | 모델명 + manual·firmware·recall | 공식적으로 확인된 문제와 개선 여부 |

검색 결과 설명만 인용하지 말고 원문을 연다. 빈약하면 영문명, 품번, 제품군 커뮤니티 이름으로 넓힌다.

**권장 최소 범위:** 접근 가능한 서로 다른 채널 3종 이상, 독립 원문 8개 이상. 부족하면 억지로 채우지 말고 실제 확보량을 밝힌다.

## 4. 원문에서 구조화된 증거를 뽑는다

각 원문마다 아래를 기록한다.

```text
출처/URL, 게시 시점, 제품·옵션 일치 여부
사용 기간과 환경
구체적 장점과 단점
고장·반품·AS와 후속 업데이트
광고·협찬·제휴 가능성
주장을 뒷받침하는 짧은 근거
```

### 출처별 주의점

- **YouTube:** `youtube-content`를 사용할 수 있으면 자막 전체를 확인한다. 제목·설명만으로 사용 경험을 단정하지 않는다. 스폰서·제품 제공·제휴 링크를 표시한다.
- **쇼핑몰:** 최신순, 낮은 별점, 장기 사용 업데이트를 본다. 배송 파손과 설계 문제를 분리하고, 옵션별 리뷰가 합쳐졌는지 확인한다.
- **커뮤니티:** 원글뿐 아니라 반박, 해결 방법, 후속 고장 댓글까지 본다. 퍼 나른 글은 한 건으로 센다.
- **블로그·카페:** `내돈내산` 문구만 믿지 말고 협찬 표기와 구매 링크를 확인한다. 보도자료를 바꿔 쓴 글은 실사용 후기로 세지 않는다.
- **접근 실패:** 로그인·삭제·robots 차단이면 검색 결과 설명을 확정 근거로 쓰지 않는다.

**완료 기준:** 핵심 주장마다 원문 URL, 사용 기간, 사용 조건이 연결되어 있다.

## 5. 독립성과 증거 강도를 판정한다

### 높음

- 관련 없는 여러 채널에서 같은 현상이 반복됨
- 정확한 모델·옵션이 일치함
- 사용 기간과 재현 조건이 구체적임
- 사진, 영상, 측정값, 후속 업데이트가 있음
- 공식 지원 문서가 같은 현상을 뒷받침함

### 보통

- 독립 후기 2건 이상이 일치하지만 조건이 일부 빠짐
- 상세한 장기 후기 1건과 여러 간접 언급이 있음
- 현상은 구체적이나 발생 빈도는 알 수 없음

### 낮음

- 단일 익명 글, 검색 결과 설명, 제목만 확인됨
- 다른 세대·옵션일 수 있음
- 협찬 콘텐츠만 존재함
- 동일 사건이나 문장의 재게시임

리뷰 개수는 불량률이 아니다. `8개 중 3개가 고장` 대신 `조사한 독립 원문에서 3건 확인`이라고 쓴다.

## 6. 상충하는 후기를 지우지 말고 설명한다

차이를 만든 조건을 찾는다.

- 생산 시기·펌웨어
- 국내판·해외판
- 체형, 공간, 온도, 네트워크
- 사용 강도와 보유 기간
- 액세서리·설정·설치 방식
- 기대 수준과 비교 대상

조건을 확인하지 못하면 `평가가 상충하며 원인은 확인되지 않음`으로 남긴다.

## 7. 최종 답변 형식

```markdown
# 한줄 결론
누구에게 맞고 가장 큰 주의점이 무엇인지.

## 조사 범위
- 정확한 모델/옵션, 조사 시점
- 확인한 채널과 독립 원문 수
- 접근하지 못한 주요 출처

## 반복해서 확인된 장점
| 장점 | 사용 조건 | 독립 출처 수 | 확신도 | 근거 |

## 반복해서 확인된 단점·고장
| 문제 | 발생 조건/시점 | 독립 출처 수 | 심각도 | 확신도 | 근거 |

## 의견이 갈린 부분
- 조건에 따라 평가가 달라진 이유

## 사용자 용도에 대한 판단
- 적합 / 조건부 적합 / 비추천과 근거

## 구매 전 확인할 것
- 옵션, 개선판, AS, 반품, 소모품

## 출처
- [제목](URL) — 날짜, 채널, 확인 내용
```

URL을 주장 가까이에 둔다. 출처 목록만 길게 붙이지 않는다.

## Common Pitfalls

1. 이름이 비슷한 세대·옵션·지역판을 섞는다.
2. 별점 평균을 품질로 간주한다.
3. 검색 표본을 실제 고장률처럼 표현한다.
4. 같은 바이럴 글의 재게시를 독립 증거로 센다.
5. 오래된 펌웨어 문제를 현재 문제로 단정한다.
6. 배송·판매자 문제와 제품 자체 문제를 섞는다.
7. 접근하지 못한 출처를 본 것처럼 쓴다.
8. 사용자 조건 없이 무조건 추천한다.

## Verification Checklist

- [ ] 모델, 세대, 옵션, 지역판을 고정했다.
- [ ] 서로 다른 채널 3종 이상을 시도하고 확보 범위를 밝혔다.
- [ ] 핵심 주장을 원문 URL과 사용 조건에 연결했다.
- [ ] 광고·체험단·제휴와 출처 중복을 구분했다.
- [ ] 배송, 판매자, 제품 자체 문제를 분리했다.
- [ ] 긍정·부정·상충 근거를 모두 다뤘다.
- [ ] 리뷰 표본을 발생률로 표현하지 않았다.
- [ ] 조사 시점, 접근 실패, 불확실성을 밝혔다.
- [ ] 사용자 용도에 대한 조건부 결론을 제시했다.
