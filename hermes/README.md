# Hermes Agent

This directory manages the hand-written parts of `~/.hermes`, including a patch
against Hermes core for native omp broker authentication. Upstream Hermes itself,
provider credentials, conversation history and generated runtime state are not
vendored. Configuration is copied because Hermes rewrites it in place; shared
skill directories remain symlinks.

## Managed files

| Repository path | Live path | Purpose |
| --- | --- | --- |
| `home/config.yaml` | `~/.hermes/config.yaml` | Models, providers, tools, plugins, MCP servers and display settings. Credentials must use `${VAR}` references, not literal values. |
| `home/SOUL.md` | `~/.hermes/SOUL.md` | Agent persona |
| `home/cron/jobs.json` | `~/.hermes/cron/jobs.json` | Scheduled job definitions |
| `home/scripts/` | `~/.hermes/scripts/` | Authored helper scripts, without dependencies or runtime output |
| `home/plugins/` | `~/.hermes/plugins/` | Authored functional plugins such as `herdr-agent-state` and `orca-status`; no custom model integration plugins |
| `home/omp-broker-runtime/` | `~/.hermes/omp-broker-runtime/` | Request-scoped native SDK host, regression tests and pinned Bun dependencies; no vendored `node_modules` |
| `core-patches/omp-broker.patch` | Hermes source checkout | Native broker client, provider registration, recent-model visibility and regression coverage |
| `apply-core-patches.sh` | Run during restore or after Hermes updates | Idempotent patch application and frozen Bun dependency installation |
| `plugins.lock.json` | Sources recorded in `~/.hermes/plugins/.install-metadata.json` | Credential-free third-party Git URLs and exact commit revisions; third-party source trees are not copied |
| `home/skills/` | `~/.hermes/skills/` | Authored skill sources and retained historical bundled/official optional/hub snapshots |
| `skill-links.json` | Symlinks under `~/.hermes/skills/` | Shared skill targets, without copying their contents |
| `systemd/hermes-gateway.service` | `~/.config/systemd/user/hermes-gateway.service` | Messaging gateway and cron user service |
| `systemd/hermes-gateway.service.d/` | `~/.config/systemd/user/hermes-gateway.service.d/` | Gateway drop-ins, including `50-mise-path.conf` and the omp ordering drop-in `60-omp-auth.conf` |

`plugins.lock.json` and `skill-links.json` are generated by `capture`. Plugin
roots are discovered by `plugin.yaml`, so new authored plugins do not require a
second allowlist. Plugins already recorded by Hermes' install metadata are
represented by source/revision instead. An unrecorded Git checkout stops capture
rather than silently vendoring it.

Skill classification reads both v1 plain-name and v2 `name:hash` bundled
manifests, the installed Hermes core/optional skill trees and skill-hub install
paths. Distribution-provided and hub-installed skills are not newly captured,
even if they are absent from the core bundled manifest. Already tracked skill
snapshots are left untouched: capture does not delete existing skill snapshots.
Restore still copies those retained historical skill sources alongside authored
sources. Built-in skills come with Hermes; install any missing official optional
or other hub skills separately using Hermes' skill management.

Historical `home/memories/` snapshots remain in the repository unchanged.
They are no longer captured or restored: private long-term memory and user
profiles are outside this settings/plugin workflow. Do not include them in
targeted commits.

## Local omp integration

Hermes registers `anthropic`, `openai-codex`, `google-antigravity`, `devin` and
`commandcode` separately. Its core adapter launches a request-scoped Bun host
using the pinned native omp SDK. The host obtains credentials from the local
broker at `http://127.0.0.1:8765`, then calls the selected upstream directly.
There is no inference gateway, port 4000 listener, provider named `omp`, or custom
model provider/image plugin.

The default is provider `anthropic`, model `claude-haiku-5-5`. Images use core
provider `google-antigravity`, model `gemini-3.1-flash-image`. The
`model_visibility` policy shows releases within four calendar months and hides
unknown/future dates across cached lists, pickers and image catalogs. Explicit
inference and saved defaults remain usable: the older configured image model is
hidden from selectable lists, not silently replaced.

This snapshot does not contain broker tokens or the account vault.
`~/.omp/auth-broker.token`, the real `.env`, and provider credentials stay local.
Restore the broker and its private authentication before starting Hermes.
The broker unit lives in the managed `omp-auth-broker` skill; the captured Hermes
ordering drop-in depends on it. `hermes-gateway.service` is the messaging/cron
service and remains enabled; it is not an inference intermediary.

Shared `model-routing` and `omp-auth-broker` skills are persisted as link
metadata. Targets inside the capturing user's home are stored relative to
`HOME`, then expanded against the restoring user's home. System targets such as
`/usr/share/omarchy/default/agents/skills/omarchy` remain absolute. Restore the
corresponding omp/Omarchy skill source first; missing targets are reported rather
than replaced with stale copied skill contents.

## Frequent pull, capture, commit and push

Use a deliberate manual loop; do not schedule unattended capture, commits or
credential copying. Do not capture while another process is editing configuration
or plugin sources.

Before making changes:

```bash
repo="$HOME/workspaces/sharosoo/dotfile"
git -C "$repo" status --short
git -C "$repo" fetch origin
git -C "$repo" -c pull.rebase=false pull --ff-only
```

The command-local `pull.rebase=false` overrides this repository's rebase-enabled
pull setting without changing Git configuration. It permits an unchanged
upstream to be checked while unrelated files are dirty. Git still refuses an
update that would overwrite local changes, and `--ff-only` refuses divergence.
If either happens, stop and resolve those changes explicitly; do not reset,
clean, force-pull or automatically stash the worktree.

After changing the live Hermes setup:

```bash
"$repo/hermes/sync.sh" capture
git -C "$repo" status --short -- hermes
git -C "$repo" diff -- hermes
paths=(
  hermes/sync.sh hermes/README.md hermes/home/config.yaml hermes/home/SOUL.md
  hermes/home/cron/jobs.json hermes/home/scripts hermes/home/plugins hermes/home/skills
  hermes/systemd hermes/plugins.lock.json hermes/skill-links.json
  hermes/home/omp-broker-runtime hermes/core-patches hermes/apply-core-patches.sh
)
git -C "$repo" add -- "${paths[@]}"
git -C "$repo" diff --cached -- "${paths[@]}"
git -C "$repo" commit --only -m "feat(hermes): persist local setup" -- "${paths[@]}"
git -C "$repo" push
```

Review new files as well as tracked diffs before staging. Inspect the staged
Hermes diff for credentials, private conversations, unexpected generated files
and source changes that do not belong to this update. The path-scoped commit
leaves unrelated staged changes out of the commit; never use `git add .` or
`git add -A` for this workflow. Push only the intended current branch. If the
push is rejected, fetch and inspect the divergence instead of force-pushing.

Capture builds and validates a temporary snapshot outside the public checkout
before updating the managed paths. It refuses credential-looking literal string
values in YAML/JSON fields and service `Environment=` entries; use `${VAR}`
references instead. This guard is not a complete secret scanner: review remains
required for scripts, documentation and arbitrary file content.

Changed or removed previous snapshots are backed up locally under
`~/.hermes/state-snapshots/dotfile/capture-<timestamp>-<pid>/`. These backups are
never captured. Nothing outside this Hermes directory is staged by the commands
above.

## Restore

Requirements: Bash, `rsync`, Python 3.9+ and PyYAML for capture; a working Hermes
Git checkout, Bun and a systemd user session for restore. `HERMES_SYNC_PYTHON` can
select a Python interpreter with PyYAML. `HERMES_HOME` can override the default
live directory.

1. Install Hermes using its official installer.
2. Restore the omp auth broker and shared skill sources separately. Restore its
   private vault/token locally; do not authenticate providers separately in
   Hermes or put `.env`, auth files or token files in this repository.
3. Inspect the snapshot, then restore:

   ```bash
   repo="$HOME/workspaces/sharosoo/dotfile"
   "$repo/hermes/sync.sh" restore
   ```

   Restore copies managed local files, including retained historical skill
   snapshots, and recreates skill links. It makes
   timestamped backups of overwritten files and replaced links under
   `~/.hermes/state-snapshots/dotfile/restore-<timestamp>-<pid>/`. It does not
   delete unrelated live files, plugins or bundled skills, and leaves memories,
   `.env`, auth files and token files untouched. Both the service and drop-ins expand the
   captured `${HOME}` marker for the current user. The Omarchy skin follows
   `~/.local/state/omarchy/current/theme/hermes.yaml`.

4. Read restore's missing-plugin and missing-skill messages. Third-party plugins
   are **not installed by restore**. It prints exact commands such as:

   ```bash
   hermes plugins install https://github.com/owner/plugin \
     --ref <40-character-commit-sha> --no-enable
   ```

   Run the printed commands explicitly, review any installer prompts, then
   enable the plugins you actually want using `hermes plugins enable <name>`.
   Do not use forced reinstalls over locally edited plugins. Existing plugin
   directories are left alone; the lock file does not automatically change their
   installed revision.

5. Resolve missing shared skill targets, confirm the core patch applied, and
   confirm the local omp auth broker is ready before enabling the service:

   ```bash
   systemctl --user enable --now hermes-gateway
   ```

`restore` reloads systemd unit definitions but does not start or restart the
gateway. For the desktop app, keep the existing project convention: build with
`hermes desktop --build-only` rather than installing Omarchy's `hermes-desktop`
package; see `omarchy/NEW-PC.md`.

### Maintaining the core patch

`core-patches/base-revision` records the inspected upstream base. Restore runs
`apply-core-patches.sh`: an already-applied patch is accepted, a clean applicable
patch is applied, and a conflict stops without resetting or stashing user work.
The native SDK is installed with `bun install --frozen-lockfile`.

After a Hermes update, run `hermes/apply-core-patches.sh` again. If the upstream
change conflicts, port the patch explicitly and rerun the real chat/tool/image
smokes before updating the snapshot. Capture does not regenerate the core patch:
include both tracked changes and new core/test files when regenerating it.

When migrating an existing gateway-based installation, archive the old
`model-providers/omp`, `image_gen/omp` and experimental Claude subscription plugin,
remove their activation/install records, migrate session and cron provider/model
overrides, remove `OMP_GATEWAY_API_KEY` and the obsolete `omp` auth-pool row, and
disable the model-only `omp-auth-gateway.service`. Restore intentionally does not
delete private authentication or unrelated live plugins on another machine.

## Excluded state

Capture does not traverse the Hermes runtime, tools or account vault. Source
copies exclude `.env*`, auth/credential files, `*.token`, private keys, `.git`,
virtual environments, `node_modules`, vendored dependencies, build output,
Python bytecode, cache directories, memories, sessions, histories, logs, downloads,
databases, backups, archived skills, skill-hub state, curator/usage state and
plugin installation locks. Dependency declarations and source lockfiles remain
part of authored plugin sources.

Private memory/user-profile files and conversation/session stores are excluded
from both capture and restore, even if historical snapshots exist in the
repository. Secrets referenced by code, configuration or link metadata remain
local; shared links are never dereferenced during capture.
