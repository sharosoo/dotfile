# SKILL.md

## 목적

어색한 한국어 문장을 자연스럽게 고칩니다.

글쓴이가 말하려던 뜻은 유지합니다. 대신 문장을 다시 짜고, 말투를 자연스럽게 다듬습니다.

## 적용 대상

다음 글에 씁니다.

- 블로그 글, 에세이, 회고
- 기술 설명, 제품 소개, 마케팅 문구
- 이메일, 보고서, 발표 자료
- 번역문이나 LLM 초안

## 고치는 순서

### 1. 원래 뜻을 먼저 확인합니다

문장을 고치기 전에 무엇을 말하려는지 확인합니다.

뜻을 모르면 표현부터 고치지 않습니다.

### 2. 번역투 표현을 찾습니다

이런 표현이 많으면 문장이 딱딱해집니다.

- "~에 대한", "~을 통해", "~에 있어서", "~로서의"
- "존재하다", "요구된다", "이루어지다"
- "~라고 할 수 있습니다", "중요한 역할을 합니다"
- "세 가지 축", "핵심 요소", "관점", "측면", "차원"처럼 내용을 대신해 글의 틀만 세우는 말
- "이 점", "이 부분", "그 상태"처럼 대상을 흐리게 가리키는 말

다만 이런 표현이 보인다고 무조건 지우지는 않습니다. 문맥에 꼭 필요하면 남깁니다.

### 3. 한국어 순서로 다시 씁니다

어색한 문장은 단어 하나만 바꿔서는 잘 고쳐지지 않습니다.

원래 뜻을 유지하면서 한국어에서 자연스러운 순서로 다시 씁니다.

```md
나쁨: 진지하고 솔직한 설명이 있었습니다.
좋음: 그는 진지하고 솔직하게 설명했습니다.
```

### 4. 명사에 갇힌 뜻을 동사와 형용사로 되살립니다

영어는 명사구를 중심으로 뜻을 쌓는 경우가 많지만, 한국어는 동사와 형용사로 움직임이나 상태를 바로 서술할 때 자연스러운 경우가 많습니다.

영어 명사마다 한국어 명사를 하나씩 대응시키지 않습니다. 먼저 그 명사가 어떤 행동이나 변화를 가리키는지 풉니다. 그런 다음 “누가 무엇을 했는지”, “무엇이 어떻게 달라졌는지”를 서술어로 씁니다.

```md
나쁨: 사용자 이탈 원인에 대한 분석을 진행했습니다.
좋음: 사용자가 왜 떠나는지 분석했습니다.

나쁨: 영화는 한국 전통의 아름다운 재현이었다.
좋음: 영화는 한국의 전통을 아름답게 재현했다.
```

명사가 정확한 전문 개념이거나 문장의 초점이면 억지로 동사로 바꾸지 않습니다.

### 5. 내용을 설명하지 않는 틀은 걷어냅니다

LLM은 내용을 실제보다 짜임새 있어 보이게 하려고 임의의 분류와 대칭 구조를 자주 만듭니다. 원문에 없는 체계를 덧씌우지 않습니다.

- 셋으로 나눌 이유가 없는데 “세 가지 축”, “세 가지 핵심 요소”, “세 가지 관점”으로 묶지 않습니다.
- “축”, “기둥”, “레이어”, “프레임워크”, “차원”, “측면”이 실제 관계를 설명하지 않으면 구체적인 대상을 바로 씁니다.
- “단순히 X가 아니라 Y”, “X를 넘어 Y”, “도전과 기회” 같은 대구를 자동으로 만들지 않습니다.
- “핵심은”, “정리하면”, “결론적으로” 뒤에서 앞말을 되풀이하지 않습니다.
- 근거 없이 “중요한 전환점”, “핵심 역할”, “의미 있는 시사점”, “새 지평”처럼 의미를 부풀리지 않습니다.
- 비슷한 길이의 소제목이나 글머리표를 기계적으로 맞추지 않습니다.

```md
나쁨: 이 제품은 속도, 정확성, 안정성이라는 세 가지 축에서 평가할 수 있습니다.
좋음: 이 제품을 평가할 때는 속도와 정확성, 안정성을 따져야 합니다.
```

다만 실제 좌표축, 분석 모형, 조직의 공식 전략처럼 “축”이나 “차원”이 관계를 정확히 나타내면 그대로 씁니다. 항목이 실제로 셋이고 목록이 이해에 도움이 될 때도 셋이라는 이유만으로 풀어 쓰지 않습니다.

### 6. 주어와 서술어를 맞춥니다

문장이 길어지면 주어와 서술어가 어긋나기 쉽습니다.

특히 "~하는 것", "~다는 점"으로 시작한 문장은 끝까지 읽어 보고 주어와 서술어가 맞는지 봅니다.

```md
나쁨: 그가 진지하게 말한 것은 그 자리에서는 누구도 반박할 수 없었습니다.
좋음: 그는 진지하게 말했고, 그 자리에서는 누구도 반박할 수 없었습니다.
```

### 7. 지시어를 구체적으로 바꿉니다

"그 일", "이 점", "이 부분"처럼 가리키는 대상이 분명하지 않은 말은 독자가 바로 알아보기 어렵습니다.

무엇을 가리키는지 다시 써 줍니다.

```md
나쁨: 어제 그 일을 처리하지 못했습니다. 이 점 때문에 오늘 일정이 늦어지고 있습니다.
좋음: 어제 보고서 마감을 못 했습니다. 그래서 오늘 발표 준비가 늦어지고 있습니다.
```

### 8. 필요 없는 문장은 뺍니다

앞 문장을 되풀이하거나 질문과 상관없는 문장은 뺍니다.

각 문단에 새로운 사실, 근거, 판단 가운데 하나도 없다면 줄이거나 없앱니다. 새 문장을 억지로 붙여 마무리하지 않습니다.

```md
나쁨: 오늘은 보고서를 한 줄도 못 썼습니다. 아무것도 쓰지 못했다는 뜻입니다.
좋음: 오늘은 보고서를 한 줄도 못 썼습니다.
```

### 9. 마지막으로 소리 내어 읽습니다

소리 내어 읽다가 걸리는 곳이 있으면 아직 덜 고쳐진 문장입니다.

눈으로 볼 때는 괜찮아 보여도, 입으로 읽으면 어색한 부분이 드러납니다.

## 자주 고치는 표현

| 어색한 표현 | 자연스러운 방향 |
| --- | --- |
| ~에 대한 질문 | ~을 묻는 질문 |
| ~을 통해 | ~로, ~하면서, ~해서, ~덕분에 |
| ~에 있어서 | ~에서, ~할 때, 삭제 |
| ~로서의 | ~인, ~로 사는, ~의 |
| 존재하다 | 있다 |
| 위치하다 | 있다 |
| 가지고 있다 | 있다, 지녔다, 믿는다, 느낀다 |
| 요구된다 | 해야 한다, 필요하다 |
| 이루어지다 | 하다, 생기다, 벌어지다 |
| 설명이 있었다 | 설명했다 |
| 중요한 역할을 한다 | 중요하다, 도움이 된다 |
| 영향을 미친다 | 바꾼다, 흔든다, 영향을 준다 |
| 하나의 방식입니다 | 한 방법입니다, 그렇게 볼 수 있습니다 |
| 세 가지 축, 핵심 축 | 항목을 바로 나열하거나 서로 어떤 관계인지 구체적으로 설명 |
| 관점에서, 측면에서, 차원에서 | 무엇을 어떻게 보는지 동사로 직접 서술 |
| 단순히 X가 아니라 Y | 실제 대조가 없으면 X 또는 Y를 바로 서술 |
| X를 넘어 Y | 실제 범위가 넓어진 것이 아니면 Y를 바로 서술 |
| 도전과 기회 | 구체적인 문제와 가능한 일을 각각 서술 |
| 중요한 전환점, 의미 있는 시사점 | 무엇이 어떻게 바뀌거나 무엇을 알 수 있는지 서술 |

## 주의할 점

### 뜻을 바꾸지 않습니다

문장을 자연스럽게 고쳐도 글쓴이가 말하려던 내용은 유지합니다.

### 모든 한자어를 없애지 않습니다

쉬운 말이 항상 좋은 말은 아닙니다. 정확한 한자어는 남깁니다.

### 모든 피동형을 없애지 않습니다

도구, 제도, 상황이 중심인 문장에서는 피동형이 자연스러울 수 있습니다.

### 낱말을 금칙어로 다루지 않습니다

“축”, “관점”, “측면”, “차원” 같은 말도 문맥에 맞으면 자연스럽습니다. 낱말 하나만 보고 지우지 말고, 그 말이 실제 관계를 정확히 설명하는지 확인합니다.

AI 문체의 흔적은 오류 판정표가 아닙니다. 셋을 나열하거나 대구를 썼다는 이유만으로 고치지 않고, 상투적인 틀이 뜻보다 앞설 때만 걷어냅니다.

### 글쓴이의 톤을 지우지 않습니다

문장을 평범하게 만들려고 글의 개성을 없애면 안 됩니다.

글의 목적과 독자에 맞는 말투를 유지합니다.

## 예시

### 예시 1. "해 봅니다"를 "해 봅시다"로 바꾸는 경우

```md
원문: 주말에 오랜만에 친구를 만난다고 해 봅니다.
수정: 주말에 오랜만에 친구를 만난다고 해 봅시다.
이유: 읽는 사람에게 같이 생각해 보자고 말하는 문장이라서입니다.
```

### 예시 2. 명사가 너무 많은 문장

```md
원문: 프로젝트의 진행 상황에 대한 보고서 작성이 요구됩니다.
수정: 프로젝트 진행 상황을 보고서로 정리해 주세요.
이유: 누가 무엇을 해야 하는지 바로 보이게 고쳤습니다.
```

### 예시 3. 피동형이 어색한 문장

```md
원문: 이 제품은 많은 사람들에게 사랑받고 있습니다.
수정: 많은 사람들이 이 제품을 좋아합니다.
이유: 사람을 주어로 두면 더 자연스럽습니다.
```

### 예시 4. 지시어가 모호한 문장

```md
원문: 어제 그 일을 처리하지 못했습니다. 이 점 때문에 오늘 일정이 늦어지고 있습니다.
수정: 어제 보고서 마감을 못 했습니다. 그래서 오늘 발표 준비가 늦어지고 있습니다.
이유: "그 일"과 "이 점"이 무엇인지 다시 썼습니다.
```

### 예시 5. 마지막 문장이 필요 없는 경우

```md
원문: 오늘은 보고서를 한 줄도 못 썼습니다. 아무것도 쓰지 못했다는 뜻입니다.
수정: 오늘은 보고서를 한 줄도 못 썼습니다.
이유: 마지막 문장이 앞 문장을 되풀이해서 뺐습니다.
```

### 예시 6. 억지로 만든 세 갈래 구조

```md
원문: 이 문제는 비용, 속도, 신뢰라는 세 가지 핵심 축을 중심으로 이해해야 합니다.
수정: 이 문제를 이해하려면 비용이 얼마나 드는지, 얼마나 빠른지, 믿을 만한지를 살펴봐야 합니다.
이유: 실제 분석 모형이 아닌데도 "세 가지 핵심 축"이라는 틀부터 세워서, 따져 볼 내용을 동사로 풀었습니다.
```

## 마지막 점검

수정한 뒤에는 이것만 확인합니다.

- 뜻이 바뀌지 않았는가?
- 주어와 서술어가 맞는가?
- 지시어가 무엇을 가리키는지 분명한가?
- 명사가 뜻을 가두고 동사가 약해지지 않았는가?
- “세 가지 축” 같은 틀이 실제 내용을 설명하는가?
- 근거 없는 중요성, 대칭 구조, 요약 문장이 덧붙지 않았는가?
- 각 문단이 새로운 사실, 근거, 판단을 전하는가?
- 소리 내어 읽었을 때 자연스러운가?
