# Aside & Browser Automation Research Report

## What it is

- **Aside browser agent**: Aside (by Aside HQ / at-inc, [aside.com](https://aside.com) / [asidehq.com](https://asidehq.com)) is an AI-powered autonomous browser and desktop application from a Y Combinator (Fall 2025) startup designed to complete real-world work across logged-in websites, SaaS tools, and personal context. ([GitHub: at-inc](https://github.com/at-inc), [Latent Space: agent-browser-tools-compared](https://jaesolshin.com/posts/agent-browser-tools-compared/))
- **Benchmark performance**: Aside self-reported a 297/300 (99.0% raw, 99.3% excluding impossible tasks) pass rate on the Online-Mind2Web benchmark, alongside evaluations on BU-Bench V1 and Odysseys across live websites using `gpt-5.5` (openai-codex). ([at-inc/aside-benchmarks: README.md:1-35](https://github.com/at-inc/aside-benchmarks/blob/main/README.md))
- **Dual execution surfaces**: Aside exposes two primary interfaces for agents via its CLI (`~/.local/bin/aside`):
  1. `aside exec <prompt>`: Spawns an autonomous subagent session executing high-level tasks in natural language, streaming thought and tool activity. ([joonlab/aside-browser: SKILL.md](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser), [esc5221/aside-remote: runner.py:11-17](https://github.com/esc5221/aside-remote/blob/main/runner.py))
  2. `aside repl "<code>"`: Provides a low-level, Playwright-compatible JavaScript REPL for deterministic DOM inspection, accessibility snapshots, screenshots, downloads, and clicks. ([joonlab/aside-browser: SKILL.md](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **MCP server integration**: Aside includes `aside mcp`, a persistent stdio JSON-RPC MCP server that exposes a single tool (`repl`) with full browser execution power, maintaining an in-memory REPL state for up to 30 minutes of idle time (`replIdleTimeoutMs=1800000`). ([esc5221/aside-remote: mcp_client.py:1-7, 87-89](https://github.com/esc5221/aside-remote/blob/main/mcp_client.py), [esc5221/aside-remote: README.md:123-124](https://github.com/esc5221/aside-remote/blob/main/README.md))
- **aside-remote project**: `esc5221/aside-remote` is a lightweight Python bridge (FastAPI/uvicorn on loopback port 8799) that wraps desktop Aside to provide a mobile/web chat interface, live tab thumbnail previews, and conversation management behind Tailscale or Cloudflare Access. ([esc5221/aside-remote: README.md:1-33](https://github.com/esc5221/aside-remote/blob/main/README.md))

## Architecture (how it drives the browser)

- **Local daemon process**: Aside runs a background daemon listening on loopback port 21420 (`http://127.0.0.1:21420`). Write endpoints require challenge signing via an installation key kept in the macOS Keychain (returning HTTP 401 otherwise), while read endpoints like `/health` are public. ([esc5221/aside-remote: README.md:114-117](https://github.com/esc5221/aside-remote/blob/main/README.md), [esc5221/aside-remote: config.py:77](https://github.com/esc5221/aside-remote/blob/main/config.py))
- **Chrome extension relay bridge**: Aside connects to the user's running Chrome instance via a dedicated Chrome DevTools Protocol (CDP) extension relay bridge ("확장↔데몬 브리지"). ([esc5221/aside-remote: browser.py:5-6](https://github.com/esc5221/aside-remote/blob/main/browser.py))
- **No separate browser process or profile**: Unlike sandboxed testing tools, Aside attaches directly to the user's live browser profile with existing logins, session cookies, and active tabs. ([Latent Space: agent-browser-tools-compared: Table 1](https://jaesolshin.com/posts/agent-browser-tools-compared/))
- **PTY requirement for CLI execution**: `aside exec` outputs 0 bytes when spawned over a pipe; it strictly requires a pseudo-terminal (PTY) to execute, outputting only its final response on the TTY while streaming intermediate reasoning and tool calls exclusively into local log files. ([esc5221/aside-remote: runner.py:3-7, 118-128](https://github.com/esc5221/aside-remote/blob/main/runner.py))
- **Filesystem session streaming**: Real-time agent streaming is accomplished by tailing `~/.aside/u/<account>/sessions/<timestamp>_<id>/messages.jsonl`, which writes structured JSON lines containing roles, reasoning/thinking blocks, and tool executions. ([esc5221/aside-remote: sessions.py:3-7, 216-254](https://github.com/esc5221/aside-remote/blob/main/sessions.py))
- **REPL execution environment**: The REPL environment runs ES2023+ JavaScript with injected globals: `page` (current active tab), `tabs` (array of open tabs), `listBrowserTabs()`, `attachBrowserTab(targetId)`, `attachActiveBrowserTab()`, `openTab(url)`, `closeTab(tab)`, `snapshot(page, options)`, `annotatedScreenshot(page)`, `sleep(ms)`, `fetch(url)`, `display(base64)`, and `pwd`. ([joonlab/aside-browser: SKILL.md](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **Sandbox boundaries in REPL**: In Aside REPL, `require()` and `child_process` are blocked (`typeof require === "undefined"`). Filesystem access (`fs`) is sandboxed to project/session roots and the Aside user directory (`~/.aside/u/0`), rejecting paths outside the agent root. ([esc5221/aside-remote: README.md:125-127](https://github.com/esc5221/aside-remote/blob/main/README.md), [joonlab/aside-browser: SKILL.md](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **Restricted Chrome extension APIs**: Inside the REPL, `chrome.tabs.query({})` is permitted, but mutating calls like `chrome.tabs.reload()` and `chrome.tabs.update()` are blocked with: `"chrome.tabs.reload/update is unavailable in the REPL because it can modify the user's tab or window session. Use openTab(url) and closeTab(page)"`. ([esc5221/aside-remote: browser.py:7-11](https://github.com/esc5221/aside-remote/blob/main/browser.py), [esc5221/aside-remote: README.md:128-130](https://github.com/esc5221/aside-remote/blob/main/README.md))

## Focus/background handling

- **Aside operates real user tabs without isolation**: Aside has zero window/tab isolation. A tab opened with `openTab()` is placed directly in the user's browser, and when `openTab()` runs, it immediately activates the tab: `✔︎ Opened a new tab and set it active: tabs[0], page → ...`. ([Latent Space: agent-browser-tools-compared: "The structures differ"](https://jaesolshin.com/posts/agent-browser-tools-compared/), [at-inc/aside-benchmarks: bu-trajectory.txt:2-3](https://github.com/at-inc/aside-benchmarks/blob/main/bu-bench-v1/results/gpt55-20260524/0a8d83a8-32c5-4609-ac78-2e8c784315bb/bu-trajectory.txt))
- **Direct focus stealing hazard in Aside**: When an agent calls `openTab()`, switches tabs, or triggers `bringToFront()`, it raises the user's tab. Jaesol Shin notes: *"ego separates the agent's tabs from the user's; Aside operates the user's real tabs. Isolation: none. a tab from openTab is a user tab. If the user is browsing alongside the agent, that one row is effectively the whole decision. ego won't touch their windows. Aside can't avoid it."* ([Latent Space: agent-browser-tools-compared: Section "The structures differ"](https://jaesolshin.com/posts/agent-browser-tools-compared/))
- **Graceful degradation on focus failure**: When attempting to focus a tab via `focus_tab(target_id)`, Aside wraps `pg.bringToFront()` in a `try/catch`. If `bringToFront()` is blocked or fails, it proceeds with the attached tab and returns `{ ok: true, focused: false }`. ([esc5221/aside-remote: browser.py:246-257](https://github.com/esc5221/aside-remote/blob/main/browser.py))
- **Focus-free background screenshot capture**: In `aside-remote`, background screenshots for tab previews attach to the target via `attachBrowserTab(targetId)` and call `pg.screenshot({ type: 'jpeg' })` **without calling `bringToFront()`**, allowing background tab captures without raising or activating the tab. ([esc5221/aside-remote: browser.py:165-175](https://github.com/esc5221/aside-remote/blob/main/browser.py))
- **The sleeping/unloaded tab trap (`status: "unloaded"`)**: In real Chrome browsing sessions, Chrome memory saver unloads inactive background tabs. In live measurements, out of 177 open tabs, **126 were in `status: "unloaded"`**. Attaching to an unloaded tab causes `CDP command timeout: Page.enable` (hanging >30 s) and can crash the extension-daemon bridge. ([esc5221/aside-remote: browser.py:4-6](https://github.com/esc5221/aside-remote/blob/main/browser.py))
- **Sleeping tab prevention**: `aside-remote` queries Chrome tabs via `chrome.tabs.query({})`, checks `loaded: false` / `status === 'unloaded'`, and rejects calls with `TabAsleep` rather than attempting a CDP attach. Because `chrome.tabs.update()` is blocked, the only way to awaken an unloaded tab is `openTab(url)`. ([esc5221/aside-remote: browser.py:7-10, 123-128, 220-221](https://github.com/esc5221/aside-remote/blob/main/browser.py))
- **Attach timeout race**: Because attaching to background tabs can hang indefinitely in the CDP relay, all attachment calls must be wrapped in a strict timeout race (`Promise.race([attachBrowserTab(tid), timeout(12000)])`). ([esc5221/aside-remote: browser.py:28, 64-74](https://github.com/esc5221/aside-remote/blob/main/browser.py))
- **Focus emulation for background tab screenshots (`Emulation.setFocusEmulationEnabled`)**: In state-of-the-art background CDP drivers (`chrome-cdp-ex`), capturing a background or minimized tab often times out after 3 s because Chromium does not render frames for inactive tabs. When plain `Page.captureScreenshot` times out on a `hidden` tab, enabling focus emulation via CDP `Emulation.setFocusEmulationEnabled({ enabled: true })` makes `document.visibilityState` visible and renders the frame in ~100 ms without raising the OS window or activating the tab. The driver immediately disables focus emulation in a `finally` block (`{ enabled: false }`). ([EndeavorYen/chrome-cdp-ex: docs/reference.md:552-553](https://github.com/EndeavorYen/chrome-cdp-ex/blob/main/docs/reference.md), [EndeavorYen/chrome-cdp-ex: scripts/cdp.mjs:5879-5907](https://github.com/EndeavorYen/chrome-cdp-ex/blob/main/skills/chrome-cdp-ex/scripts/cdp.mjs))
- **Unfocused window creation**: In CDP background mode, opening a new tab uses `Target.createTarget({ newWindow: true, background: true })` instead of creating a tab in the current window. A tab created with `background: true` inside an existing window is placed behind the user's active tab and stays permanently occluded (`document.visibilityState: hidden`), dropping input and stalling screenshots. Creating an unfocused window isolates the tab from the user's active tabs. ([EndeavorYen/chrome-cdp-ex: docs/reference.md:550-551](https://github.com/EndeavorYen/chrome-cdp-ex/blob/main/docs/reference.md), [EndeavorYen/chrome-cdp-ex: scripts/cdp.mjs:32430-32431](https://github.com/EndeavorYen/chrome-cdp-ex/blob/main/skills/chrome-cdp-ex/scripts/cdp.mjs))
- **Chromium occlusion flags**: When running against a headed browser in the background, Chromium throttles occluded windows unless launched with `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding`, and `--disable-background-timer-throttling`. Without these flags, Chrome marks covered windows as hidden, causing clicks to be dropped or delayed by ~3 s. ([EndeavorYen/chrome-cdp-ex: docs/daily-browser-cdp.md:27-34](https://github.com/EndeavorYen/chrome-cdp-ex/blob/main/docs/daily-browser-cdp.md), [EndeavorYen/chrome-cdp-ex: docs/reference.md:558, 569](https://github.com/EndeavorYen/chrome-cdp-ex/blob/main/docs/reference.md))
- **Linux/Wayland/Hyprland window focus stealing suppression**: On Hyprland/Wayland, when Chrome receives an activation request or spawns a window, Hyprland window rules must be configured to suppress window raising:
  - `windowrulev2 = noinitialfocus, class:^(google-chrome.*)$`
  - `windowrulev2 = suppressevent activate, class:^(google-chrome.*)$`
  - `misc:focus_on_activate = false` in `hyprland.conf`. Without these rules, any browser action that requests window focus will pull the active workspace or steal keyboard input from the user's terminal/editor. ([Hyprland Wiki: Window Rules](https://wiki.hyprland.org/Configuring/Window-Rules/))

## Conventions / rules it imposes on agents

- **Inspect open tabs before touching the browser**: In `aside-browser` skill, agents must never assume `page` is the user's current tab. Agents must run `listBrowserTabs()` first and only call `attachActiveBrowserTab()` if the user explicitly asks about their active tab, or `attachBrowserTab(targetId)` if referencing a specific tab. ([joonlab/aside-browser: SKILL.md: "Open browser tabs"](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **Avoid attaching to active tabs during background work**: In background or parallel operations, agents must operate only on their own `openTab()` handle and explicitly avoid `attachActiveBrowserTab()` to prevent contention with the human user. ([joonlab/aside-browser: SKILL.md: "Single shared browser instance"](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **Accessibility snapshots as primary observation**: Agents must always use `snapshot(page, { interactive: true })` as the primary way to read pages, which returns `{ tree, diff }` with compact ARIA roles and virtual locator references (`[ref=e1]`, `[ref=e2]`). ([joonlab/aside-browser: SKILL.md: "Snapshot"](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **Strict ban on snapshot truncation**: Agents are forbidden from truncating snapshot outputs with `.substring()`, `.slice()`, or `.split()`. If an agent attempts this, Aside injects an explicit system warning: `[system][warning] DO NOT USE tree.substring() - you're hiding important context from snapshot. don't hesitate to print the full tree or diff.` ([at-inc/aside-benchmarks: bu-trajectory.txt:3, 12, 14, 17](https://github.com/at-inc/aside-benchmarks/blob/main/bu-bench-v1/results/gpt55-20260524/0e2e0517-ccf8-483e-8693-b60cf35216bd/bu-trajectory.txt))
- **Diff-based token economization**: After the initial tree snapshot, agents must inspect `s.diff` instead of reprinting `s.tree`. In-page changes show an 89.1% character savings (50,818 chars for tree vs 5,529 chars for diff). ([Latent Space: agent-browser-tools-compared: Table "Observation APIs"](https://jaesolshin.com/posts/agent-browser-tools-compared/), [joonlab/aside-browser: SKILL.md: "Snapshot"](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **Ref invalidation lifecycle**: Every new snapshot invalidates all previously generated ref IDs. Actions must use ref IDs directly in `page.locator('e1').click()`, but never mix virtual ref IDs into CSS selectors or treat them as real DOM attributes. ([joonlab/aside-browser: SKILL.md: "Snapshot"](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **Tab limit and hygiene warnings**: Aside monitors the open tab count and actively warns agents when 5 or more tabs remain open: `[warning] 5 tabs are open. Close tabs you do not need as you work.` When the last tab is closed, Aside sets `page = null` and prompts: `[system] last tab closed. page is now null. call openTab(url) to open a new one.` ([at-inc/aside-benchmarks: bu-trajectory.txt:28, 30, 33, 34](https://github.com/at-inc/aside-benchmarks/blob/main/bu-bench-v1/results/gpt55-20260524/3e26342c-747e-4193-b14d-f33b12c76481/bu-trajectory.txt))
- **Mandatory tab lifecycle methods**: Agents must strictly manage tabs with `openTab()` and `closeTab()`. Using Playwright's `page.context().newPage()` or `page.close()` causes memory leaks in the Aside runtime. ([joonlab/aside-browser: SKILL.md: "Navigation and Actions"](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **No speculative sleep delays**: `openTab()` and `.click()` internally wait for DOM stability and interactivity. Agents are instructed never to add redundant `sleep()` calls immediately after clicks or navigations unless observing an asynchronous animation or transition. ([joonlab/aside-browser: SKILL.md: "Navigation and Actions"](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **Prompt-embedded safety boundaries**: Because Aside operates on the user's live profile, destructive actions (submitting orders, deleting emails, changing settings) must be guarded by explicit prompt constraints (e.g. "read only; do not submit/send/delete/invite/share"). Aside adheres to these constraints reliably. ([joonlab/aside-browser: SKILL.md: "exec — Verified Notes"](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))

## Ideas worth copying

- **Temporary focus emulation for background screenshots**:
  - Implement the `chrome-cdp-ex` pattern: check `document.visibilityState`. If `hidden`, make a 3-second attempt at `Page.captureScreenshot`. On timeout, wrap the capture in `Emulation.setFocusEmulationEnabled({ enabled: true })` and turn it off in `finally`. This captures real rendered pixels from background or occluded tabs without bringing the Chrome window to the foreground or firing native OS window activations. ([EndeavorYen/chrome-cdp-ex: scripts/cdp.mjs:5879-5907](https://github.com/EndeavorYen/chrome-cdp-ex/blob/main/skills/chrome-cdp-ex/scripts/cdp.mjs))
- **Sleeping tab preflight check**:
  - Before calling `Page.enable` or `DOM.enable` on a tab target, inspect its status via `chrome.tabs.query({})` (or Target metadata). If `status === 'unloaded'` or `discarded: true`, avoid attaching directly. Either warn the user, or awaken it safely by navigating a fresh target or calling `openTab(url)`. This eliminates 30-second CDP hangs. ([esc5221/aside-remote: browser.py:4-10, 123-128](https://github.com/esc5221/aside-remote/blob/main/browser.py))
- **Attachment timeout race (`Promise.race`)**:
  - Always bound target attachment with an explicit timeout race (e.g. 10–12 s). In CDP extension relays, tabs that are terminating or frozen by Chrome memory saver will never respond to `Target.attachToTarget` or `Debugger.attach`, causing agent processes to hang indefinitely. ([esc5221/aside-remote: browser.py:64-74](https://github.com/esc5221/aside-remote/blob/main/browser.py))
- **Tab ownership tracking (`openedBy`)**:
  - Adopt ego-browser's tab ledger model: record whether a tab was opened by `agent` or `user`. Agents may only close tabs where `openedBy === 'agent'`. Unmanaged user tabs are marked read-only / protected, preventing accidental destruction of user sessions during task cleanup. ([citrolabs/ego-lite: skills/ego-browser/SKILL.md:121-124, 457-460](https://github.com/citrolabs/ego-lite/blob/main/skills/ego-browser/SKILL.md))
- **Enforced tab count warnings**:
  - Emit an interactive system warning when the agent holds 5 or more open tabs. Agents frequently forget to close intermediate research tabs, leading to resource bloat in the user's real browser. ([at-inc/aside-benchmarks: bu-trajectory.txt:28, 30, 33](https://github.com/at-inc/aside-benchmarks/blob/main/bu-bench-v1/results/gpt55-20260524/3e26342c-747e-4193-b14d-f33b12c76481/bu-trajectory.txt))
- **Token-efficient accessibility diffs (`{ tree, diff }`)**:
  - Return accessibility snapshot diffs between consecutive actions. Printing only the subtree delta reduces token usage by up to 89% on rich dynamic web applications. ([Latent Space: agent-browser-tools-compared: Section "Observation APIs"](https://jaesolshin.com/posts/agent-browser-tools-compared/))
- **Safe background browser launch flags**:
  - When starting Chrome for agent use, pass `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding`, and `--disable-background-timer-throttling` to ensure background tabs continue rendering and processing JavaScript timers without dropping input. ([EndeavorYen/chrome-cdp-ex: docs/daily-browser-cdp.md:27-34](https://github.com/EndeavorYen/chrome-cdp-ex/blob/main/docs/daily-browser-cdp.md))
- **Hyprland / Omarchy Wayland window rules**:
  - Add `windowrulev2 = noinitialfocus, class:^(google-chrome.*)$` and `misc:focus_on_activate = false` in the user's desktop configuration to prevent browser tabs from stealing workspace focus on Linux. ([Hyprland Wiki: Window Rules](https://wiki.hyprland.org/Configuring/Window-Rules/))

## Unverified

- **Aside daemon Linux binaries**: Aside's official desktop app and CLI are distributed primarily for macOS (arm64); native Linux packages for the closed-source daemon (`aside`) are unconfirmed and not publicly hosted on their repository. ([esc5221/aside-remote: README.md:36-37](https://github.com/esc5221/aside-remote/blob/main/README.md), [citrolabs/ego-lite: README.md](https://github.com/citrolabs/ego-lite/blob/main/README.md))
- **Non-activating tab creation in Aside**: Whether Aside's closed-source daemon supports an internal option or parameter for `openTab(url, { active: false })` to prevent tab activation upon creation is unverified, as the public REPL only exposes `openTab(url)`. ([joonlab/aside-browser: SKILL.md](https://skillsmp.com/creators/joonlab/joonlab-claudecode-setting-for-share/claude-skills-aside-browser))
- **`Page.setWebLifecycleState` necessity**: While `chrome-cdp-ex` reports that `Emulation.setFocusEmulationEnabled` alone is sufficient to capture hidden tabs, certain community reports claim `Page.setWebLifecycleState({ state: 'active' })` is needed on older Chromium versions (pre-130) to prevent background timer freeze. ([EndeavorYen/chrome-cdp-ex: Issue #535](https://github.com/EndeavorYen/chrome-cdp-ex/issues/535))
