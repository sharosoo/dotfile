# Korean (한국어) — 서술어 중심 교정 가이드

LLM 한국어는 “한국어답게 써라”만으로는 잘 안 풀립니다.
서술어 중심으로 다시 쓰고, 명사화·피동·A는 B 구조·직역어를 따로 잡는 교정 루프가 필요합니다.

## 핵심 원칙 (가장 중요)

한국어 문장은 **서술어가 중심**입니다.
국립국어원 『새국어생활』도 서술어가 주어·목적어·보어·필수 부사어를 결정한다고 설명합니다.
호응은 문법 조건뿐 아니라 의미 조건도 맞아야 합니다.

**교정 순서**:
서술어 확인 → 주어·목적어 확인 → 문장 구조 교체 → 단어 교체

단어 교체부터 하면 안 됩니다.

---

## 1. 문장을 짧게 나눕니다

LLM 문장은 한 문장에 여러 일을 넣습니다.

**나쁜 예**:
시간축을 기준으로 사용자의 행동 패턴을 분석하는 것이 서비스 개선의 가능성을 도출하는 핵심입니다.

**좋은 예**:
사용자의 행동이 시간에 따라 어떻게 달라지는지 봅니다.
그 결과를 바탕으로 서비스를 어디서 고칠지 찾습니다.

이렇게 나누면 번역투·주술 호응·명사 나열이 함께 줄어듭니다.

---

## 2. “A는 B입니다”를 동사 문장으로 바꿉니다

LLM은 정의문을 자주 씁니다.

**LLM식**:
이 접근법의 핵심은 확장성입니다.

**고친 문장**:
이 방식은 쉽게 확장할 수 있습니다.

**자주 바꿀 패턴**:

| LLM식                  | 고친 표현                     |
|------------------------|-------------------------------|
| 목표는 응답 속도의 개선입니다 | 응답 속도를 높입니다         |
| 문제는 데이터 정합성입니다   | 데이터가 서로 맞지 않습니다   |
| 핵심 요소는 사용자 편의성입니다 | 사용자가 쉽게 쓸 수 있어야 합니다 |

기준: “A는 B입니다”가 이어지면 B를 동사나 형용사로 풀어 씁니다.

---

## 3. 명사화를 동사로 풉니다

LLM은 동작을 명사로 바꿉니다.

**LLM식**:
문제 해결을 위한 분석의 수행이 필요합니다.

**고친 문장**:
문제를 해결하려면 먼저 분석해야 합니다.

**자주 나오는 명사화**:

| 의심 표현         | 고치는 방향             |
|-------------------|-------------------------|
| 개선이 필요합니다 | 개선해야 합니다        |
| 검토가 요구됩니다 | 검토해야 합니다        |
| 확인이 가능합니다 | 확인할 수 있습니다     |
| 분석의 수행       | 분석합니다             |
| 문제 해결의 추진  | 문제를 해결합니다      |

본문에서는 동사로 푸는 편이 자연스럽습니다.

---

## 4. 피동형을 능동형으로 바꿉니다

LLM은 책임 주체를 흐리기 위해 피동형을 자주 씁니다.

**LLM식**:
개선 작업이 수행됩니다.

**고친 문장**:
팀이 개선 작업을 합니다.

**주체가 중요하지 않으면 더 짧게**:
개선합니다.

**자주 바꿀 표현**:

| LLM식 표현           | 고친 표현       |
|----------------------|-----------------|
| 수행됩니다           | 합니다         |
| 진행됩니다           | 합니다         |
| 처리됩니다           | 처리합니다     |
| 검토됩니다           | 검토합니다     |
| 개선이 이루어집니다  | 개선합니다     |

---

## 5. 주어·목적어와 서술어의 호응을 봅니다

이 단계가 가장 중요합니다.
LLM 문장은 단어 뜻은 맞지만 결합이 어색합니다.

**나쁜 예**:
전략을 증가합니다.

**좋은 예**:
전략을 강화합니다.
전략을 새로 세웁니다.

**검사 질문** (4개면 충분):
1. 이 서술어는 무엇을 주어로 요구합니까?
2. 이 서술어는 목적어를 요구합니까?
3. 지금 붙은 명사가 이 동사와 자연스럽습니까?
4. 명사를 바꿀지, 동사를 바꿀지 정해야 합니까?

---

## 6. 직역어를 문맥어로 바꿉니다

| 직역투 표현     | 더 자연스러운 표현             |
|-----------------|--------------------------------|
| 시간축          | 시간 흐름 / 시점 / 기간 / 순서 |
| 맥락에서        | 이 경우 / 이 상황에서          |
| 측면에서        | 점에서 / 보면                  |
| 접근법          | 방식 / 방법                    |
| 요소            | 부분 / 점 / 항목               |
| 도출하다        | 끌어내다 / 찾다 / 정리하다     |
| 활용하다        | 쓰다                           |
| 기반으로        | 바탕으로 / 써서                |
| 가능성을 제시하다 | 할 수 있음을 보이다           |

**예**:
시간축을 기준으로 오류 발생 패턴을 분석합니다.
→ 시간이 지나며 오류가 어떻게 생기는지 봅니다.

---

## LLM에 맡길 때의 프롬프트 (권장)

```
다음 글을 한국어로 처음 쓴 문서처럼 고쳐 주세요.
규칙:
1. 한 문장에는 하나의 생각만 담아 주세요.
2. "A는 B입니다" 구조가 반복되면 동사나 형용사 문장으로 바꿔 주세요.
3. 명사화 표현을 동사 표현으로 풀어 주세요.
   예: 개선이 필요합니다 → 개선해야 합니다.
4. 피동형을 줄이고, 가능한 경우 능동형으로 바꿔 주세요.
5. 주어, 목적어, 서술어가 자연스럽게 호응하는지 확인해 주세요.
6. 영어 직역어를 문맥에 맞는 한국어 표현으로 바꿔 주세요.
7. "시간축", "측면", "맥락", "요소", "기반", "도출", "수행"은 꼭 필요한 경우에만 남겨 주세요.
8. 의미는 바꾸지 말아 주세요.
출력:
- 수정본
- 고친 이유 5개 이하
```

더 안정적인 결과가 필요하면 2단계로 나눕니다.

**1차**: 문장별 문제를 표시 (번역투 / 명사화 / 피동형 / A는 B / 주술 호응 / 직역어 등)

**2차**: 위 문제를 반영해 다시 작성 (의미 유지, 한국어 문서처럼 자연스럽게)

---

## 좋은 교정은 “단어 치환”이 아닙니다

**교정 전**:
시간축을 기준으로 사용자의 행동 패턴을 분석하는 것이 서비스 개선의 가능성을 도출하는 핵심입니다.

**단어만 바꾼 문장** (여전히 어색):
시간 흐름을 기준으로 사용자의 행동 패턴을 분석하는 것이 서비스 개선의 가능성을 끌어내는 핵심입니다.

**구조까지 고친 문장** (권장):
사용자의 행동이 시간에 따라 어떻게 달라지는지 봅니다.
그 결과로 서비스를 어디서 고칠지 찾습니다.

---

## 마무리 점검 (소리 내어 읽기)

1. 문장이 너무 길면 나눕니다.
2. “A는 B입니다”가 반복되면 동사 문장으로 바꿉니다.
3. “~의 ~의” 구조를 줄입니다.
4. “~성, ~화, ~적, ~측면”을 의심합니다.
5. “수행됩니다, 이루어집니다, 처리됩니다”를 능동형으로 바꿉니다.
6. 서술어마다 필요한 주어와 목적어를 확인합니다.
7. 명사와 동사가 자연스럽게 붙는지 봅니다.
8. 직역어를 문맥에 맞는 말로 바꿉니다.
9. 주어가 너무 많이 드러나면 줄입니다.
10. 마지막에 소리 내어 읽어 봅니다.

---

## 출력 계약 (기존 스킬과 동일)

- **NATURALIZED TEXT** — 최종 텍스트만
- **CHANGE LOG** — 증상 제거, 의미 영향 여부, 가정, 용어 보존 등을 명시

의미를 바꾸지 않습니다.
의미에 영향이 있는 변경은 반드시 CHANGE LOG에 플래그합니다.

---

이 가이드는 “단어 교체”가 아니라 “서술어 중심 재작성”을 핵심으로 합니다.
LLM 교정의 품질은 이 순서를 지키느냐에 따라 크게 달라집니다.
